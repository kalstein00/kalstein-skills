## What it does

Implement an explicit ordered ticket list with fresh sequential workers in one checkout. Each worker retains acceptance evidence while the parent owns broad final gates.

## When to reach for it

Invoke this orchestrator explicitly for a supplied ticket list; use implement-spec for a parallel spec graph.

## Prerequisites

The target project and the inputs/authority required by the owning task. Preserve its existing setup and documentation.

## Common questions

**Can a batch skip live UI verification until the end?**

No. Each UI ticket supplies its required live journey and inspected images; the parent refreshes evidence affected by later tickets.

## It's working if

- Tickets keep their requested order and scoped commits.
- The final batch report carries UI observations and images and distinguishes deferred from completed gates.
