# Library Docs

Resolve the target project's copied-documents lock/manifest, installed search CLI, package/snapshot pin, and configured shared caches from its instructions. The plugin does not ship a documentation engine or copied library corpus. Use that project's public CLI and installed help with its configured paths, engine/model, cache, and library scope.

1. Inspect only the requested library's lock entry and manifest. Establish the resolved dependency version from its lock and installed package when available; disclose discrepancies. Separately identify the document snapshot/revision and upstream source release/tag or rolling status. A target packageVersion label and a legacy snapshot name do not establish source compatibility.
2. Search a short query that preserves API identifiers, error strings, versions, and negative conditions. Use English for an English source corpus while answering in the user's language. Serialize operations against the same index cache. Verify the returned status and exact requested scope; ranking is a discovery aid, not proof.
3. Select only directly relevant results. Read bounded source ranges when an excerpt is insufficient, rather than dumping every top result. For the requested use, establish relevant parameter/default meanings, prerequisites, return or completion guarantees, and event/lifecycle ordering rather than API existence alone. If the source does not support the claim, narrow the query based on the concrete gap or report partial/no evidence.
4. Cite the resolved library version, document snapshot/revision, upstream source identity, URL and selected range. State whether the requested contract is version-matched, supported despite a source-version difference, or unresolved. When versions differ or the source is rolling, compare only the needed contract with matching official documentation, types or source through the project's fallback route. A name/signature match alone does not prove behavioral compatibility. Use separate explicit pins for version comparisons; preserve existing pins and source files rather than changing them to obtain a preferred answer.
5. When preparation is missing, inspect the actual error and reuse the existing shared cache and pinned engine/model. Perform authorized preparation for the requested scope; distinguish missing, incompatible, stale, and corrupt states. Preserve old evidence and versions. Preparation is not permission to delete caches, re-scrape sources, rewrite copied documents, or update dependencies.

If the project has no copied package, follow its documented fallback, normally the library's official documentation. State which source route was used. If project instructions require copied evidence and it remains unavailable, report that missing capability before behavior-sensitive edits. Do not silently change library scope, model, or retrieval mode to manufacture a successful lookup.
